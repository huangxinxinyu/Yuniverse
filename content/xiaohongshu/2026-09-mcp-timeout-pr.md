# 本想定时发帖，结果提了个 PR

本来只是想让 Codex 定时发一篇小红书，结果重试了好几次都失败，就很莫名其妙。之前用 Codex 发帖一直很顺畅，这次 MCP 只报超时，也没有具体错误码。

翻日志发现，程序甚至还没走到“设置定时发布”，而是卡在了标签处理。

这个 MCP 不是直接调用小红书的发布 API，而是在浏览器里模拟人操作。处理标签时，它会先在正文里输入 `#` 和标签名称，等小红书弹出联想框，再点击第一条结果，把这段文字变成正式话题。

原来的代码会用 `page.Element(...)` 查找这个联想框。本来的设计是：找到就点击话题；找不到就输入一个空格，把 `#标签` 作为普通文本保留下来。

但 `page.Element(...)` 的实际行为不是“找一次”，而是“持续等待，直到元素出现”。当某个标签没有触发联想框时，程序不会进入备用流程，而是一直等到整个页面超时。

改成 `page.Has(...)` 后，程序只检查当前有没有联想框：有就点击，没有就马上走备用流程，然后继续发布。

补完回归测试后，我给 xiaohongshu-mcp 提了 PR #854。
